# Questions for the reviewing pharmacist

Two modelling assumptions in `packages/core/src/formulary` (spec: `.kiro/specs/formulary`) need a licensed pharmacist's confirmation before the first entry is approved. Until they are answered, the app shows an explicit caveat (FM-14) and no medicine data is published.

## 1. Where does the refrigerated range end?
**Assumption:** a medicine is "in range" at or below **8 °C** (the upper edge of the 2 to 8 °C cold chain). The clock consumes budget only above that.
**Why it matters:** an entry with `maxTempC` below 8 °C is rejected (it cannot be represented). A label whose refrigerated range is narrower would be understated.
**Ask:** is 8 °C correct for every product we will list? If not, which products need a different edge? (That is a schema change, not a code default.)

## 2. Do in-use budgets count only time outside the fridge?
**Assumption (from `label-only-medicine.md`, rule 3):** the budget is consumed only while the temperature is above the refrigerated range and at or below the label's `maxTempC`.
**Risk if wrong:** some in-use labels count days since first opening whatever the temperature. For those, our clock would **understate** the time used.
**Mitigation shipped:** every in-use result carries the line "This counts only time outside the fridge. If your label also counts days since you first opened it, that count is separate. Check your label."
**Ask:** which products' in-use budgets are time since opening? Those need a different entry type (for example `sinceOpeningDays`) so the app can track an opening date. Until then, list them only if the caveat is acceptable.

## Release blockers outside the code
- A review key must be generated by the review pipeline and its **public** key added to `TRUST_ANCHORS` in `apps/mobile/src/data/formulary.ts` in a reviewed commit. Until then the app shows no medicine clock, by design.
- The pipeline must sign each entry over `formulary.canonicalPayload(entry)` and the snapshot over `manifestPayload(version, entrySignatures)`, both as `<keyId>.<base64url Ed25519 signature>`.
