# afterglow-formulary

The review pipeline behind Afterglow's medicine clocks. **This repository contains no drug data.** `validated/` does not exist until a licensed pharmacist approves a first entry, and until then the app shows no medicine clock, by design (`.kiro/steering/label-only-medicine.md`).

It is built inside the Afterglow workspace so it shares the app's own verifier and the repository's guardrails. It is designed to be lifted out as its own repository, `afterglow-formulary`, unchanged.

## What the app trusts, and why

The app shows a medicine clock only for an entry that:

1. carries a signature that verifies against a public key **pinned in the app** (`TRUST_ANCHORS` in `apps/mobile/src/data/formulary.ts`), and
2. sits in a snapshot whose manifest signature also verifies and whose version is not older than the last one the device accepted.

So the numbers come from a label, were checked by a second model family, and were approved by a person who holds the signing key. A model never decides a number, and a typo in a file cannot create a clock.

## The process

```
 label text ──ingest──▶ sources/            (stored, hashed)
                           │
 Label Reader (AI, family A) writes ──▶ proposals/<id>.json
 Pharmacist Validator (AI, family B) writes ──▶ reports/<id>.json
                           │
                      review  ──▶ review-queue/<id>.json   or   rejected/<id>.json
                           │                 (checks, below)
        licensed pharmacist: approve ──▶ validated/<product>-<condition>.json   (signed)
                           │
                      snapshot ──▶ dist/snapshot.json + docs/FORMULARY.md
                           │
              copy to apps/mobile/public/formulary/snapshot.json   (a human, in a reviewed commit)
```

### What `review` checks (`.kiro/specs/formulary-pipeline`)

| Check | What it means |
|---|---|
| FP-01 | The excerpt appears word for word in the stored label text. |
| FP-02 | `maxTempC` and `maxDays` are stated in the excerpt (°C, or °F converted exactly; days, or weeks times 7). A note cannot add a number the excerpt lacks. |
| FP-03 | A different model **family** and a different model agree on the condition, temperature and days. |
| FP-04 | The proposal is about the stored source, and the app itself would accept the entry. |
| FP-09 | The stored source still matches its hash. |

These prove the numbers are in the label and two models read them the same way. They do **not** prove the extraction is clinically right (for example, which of several storage statements applies to a presentation). That is the pharmacist's job: `approve` puts the excerpt in front of them and requires an explicit `--i-have-read-the-label`.

## Commands

```sh
pnpm pipeline keygen   --id review-2026 --out ~/keys/afterglow-review.key
pnpm pipeline ingest   --id acme-label-1 --product "Acme" --label-version 2026-01 \
                       --title "Acme label" --url https://… --file label.txt
pnpm pipeline review   acme-in-use --report reports/acme-in-use.json
pnpm pipeline approve  acme-in-use --approver "Name, qualification" --date 2026-11-20 \
                       --i-have-read-the-label --key ~/keys/afterglow-review.key --key-id review-2026
pnpm pipeline snapshot --key ~/keys/afterglow-review.key --key-id review-2026
pnpm pipeline verify
```

The private key is created **outside** this folder with owner-only permissions. The pipeline refuses to write or read a key inside the repository, refuses a key file that others can read, and never prints a key. Only `anchors.json` (public keys) is kept here.

## Who may write where

| Actor | May write |
|---|---|
| Label Reader agent | `proposals/**` |
| Pharmacist Validator agent | `reports/**` (its report, passed to `review --report`) |
| The pipeline | `review-queue/**`, `rejected/**`, `reviews/log.jsonl` |
| A pharmacist, with the key | `validated/**`, only through `approve` |

The workspace hooks deny agent writes to `validated/**` (`deny-formulary-write`, `deny-formulary-write-shell`). Do not edit a validated entry by hand, even for a typo: open a proposal, review it, and approve a superseding entry (`approve … --supersede`).

## Human gates (nothing here can do these for you)

1. **A licensed pharmacist** must review and approve. No person is named in this repository.
2. **A signing key** must be generated by whoever holds the review role, kept offline, and its public half added to `TRUST_ANCHORS` in a reviewed commit.
3. **The two model runs** (Label Reader and Validator, on two different families) need AWS Bedrock access. This repository defines the files they must produce and refuses anything else; it does not call a model.
4. **The data licence** for the published table is a decision for the founder.
5. **The two modelling questions** in `docs/kiro/pharmacist-questions.md` must be answered before the first approval.

## Tests

```sh
pnpm test
```

35 tests: the checks, approval, signing, the snapshot through the app's real loader (including that changing any published byte makes the app refuse it), key handling, and the real command line end to end in a temporary directory. Every fixture is an invented product and an invented label sentence.
